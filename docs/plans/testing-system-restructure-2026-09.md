## Completion requirements

1. Preserve every current user-flow ID and every observable clause. Keep direct database, real application, and isolated component evidence distinct. Remove repeated browser setup only where another named test still proves the actual creation workflow.
2. Give each independent execution group owned data, sessions, checkpoints, and outputs. Preserve real producer dependencies inside connected journeys. A feature failure must not suppress unrelated groups, while a failed shared prerequisite must block invalid execution.
3. Explain the selected groups before execution. Changed shared or unknown inputs select broad coverage. Group fingerprints include owned source, imported dependencies, tests, execution settings, and environment identity. Documentation edits do not invalidate product proof but documentation and coverage checks remain current.
4. Reuse only successful complete group results whose qualifying inputs remain unchanged. A later failed result must invalidate an older pass. Release records must cover all required groups with exact provenance, without presenting mixed group runs as one integrated Golden run.
5. Keep scripted browser checks as the default. Shared helpers own readiness and single-write observation. Cross-session freshness must meet its two-second contract. P1-22 opening must reach usable controls within five seconds. A longer diagnostic timeout must not turn a slow result green.
6. Preserve failure evidence and cost. Block unchanged failed-group retries. Keep failure classification and owned cleanup. Test the selector, evidence reuse, missing coverage, interruption recovery, and deadline checks with deliberately invalid examples.
7. Rewrite current docs, skills, protocol, command examples, and source comments to agree with the new workflow. Mark old decisions and plans as historical where necessary. Finish with a fresh-agent navigation and contradiction review.

## Implementation record

- Run state and browser outputs now have per-run owners. Historical recovery is explicit; current runs cannot fall back to shared state. Setup and teardown no longer sweep unrelated test organizations.
- Seeding reserves and archives every cleanup identity before writes. UI signup email mints also record exact ownership before submission, including uncertain responses. Stale state saves cannot erase those emails. Partial seeds remain cleanable and cannot masquerade as diagnostic-ready worlds.
- The unused global cleanup function and lifecycle sweep callback were removed. Only recorded ownership can supply routine cleanup targets; convention checks reject restoring wildcard email discovery or organization marker queries without owned administrators.
- A machine-readable map imports 969 catalog flows and retains their attributed evidence. Two reviewed mappings record shortened correction setup with the original UI submission coverage retained. A file reference alone does not prove every clause. Changed catalog text reopens its mapping.
- The group registry separates focused Golden files and their producer closure from the complete integrated journey. Audit files are independent groups. Unit, SQL, component, static, and provider checks keep their distinct responsibilities.
- The replacement planner and executor select groups and preserve their evidence. Successful group results retain their original run/build attribution; unchanged failed results cannot be retried automatically. Blocked execution prints its reason and stores it in the report.
- Freshness records now distinguish observed correctness and responsiveness. A visible result beyond its deadline fails. Observation starts before submission, and receiving-page navigation invalidates live-delivery proof.
