# Standards audit

Status: living — last reviewed 2026-09-25; the per-aspect map of rules, automated proof and review judgment, written so a wave-end audit is a checklist, not a research task

WerkFlow holds itself to five standards: the UI and UX canon, performance and freshness, security, the testing system, and code quality. Each has one rules home, a set of automated gates that prove part of it, and a bounded list of judgments a reviewer still makes by hand. This page maps the three for each aspect and gives the procedure for auditing a wave. It states facts about where things live; it does not restate the rules.

The honest boundary: the gates prove what is registered. A new component that reuses the registered primitives inherits their contracts; a new interaction that bypasses them is caught by the lint selectors and the review checklist, not by a measurement, until it is registered as a measured scenario or a component contract. That registration is the reviewer's judgment call in every wave.

## How to audit a wave

1. Run the release plan on the wave's final tree (`bun run test:verify --mode release`) and the cloud canary; every group above runs inside it. A wave is not audited on a partial plan.
2. For each aspect, read the rules home once and walk the wave's slice records against its review-judgment column; write one finding list per aspect with file and line.
3. Check registration: every new flow the wave added is either a measured scenario, a component contract, a control-map row, a catalog clause with coverage, or an explicitly declined registration with its reason in the slice record.
4. Push every finding up the ladder ([decision 0005](../decisions/0005-enforcement-ladder.md)): a mechanism or a check where one is reachable, a backlog row otherwise. The audit's output is a set of gates, not a report.
5. Record the audit in the wave's audit ledger under `docs/plans/phase-1/audits/`, and move every lasting fact to its living home before the ledger closes (README maintenance rule 6).

The September 2026 tier audit ([pre-Wave-3 step 4](../plans/phase-1/pre-wave-3/04-wave-3-4-and-phase-2-planning.md#tier-audit-findings-2026-09-17-read-only)) is the model: 121 lessons traced to their mechanisms and homes, 18 findings, every one converted or filed.
