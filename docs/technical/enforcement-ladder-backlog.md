Stage B (2026-08-28) retired four Tier 1 rows and two Tier 2 rows by landing them, and added its own protections: the `RealtimeTable` type derives from the one `REALTIME_TABLES` list and the provider generates every binding from it, so a table cannot subscribe without its organization filter (Tier 1 by construction); `useLiveView`/`useRealtimeRouterRefresh` expose no debounce option, so the 150 ms floor cannot be undercut (Tier 1 by construction); `bun run realtime:check` — also part of the local preflight — diffs the list against the database publication and replica-identity state (Tier 2); ESLint bans async `startTransition` callbacks, `setInterval` (named wall-clock exceptions), and `useRealtimeEvent` imports outside the live-view family (Tier 2); replica identity `USING INDEX` makes the DELETE payload leak unwritable at the schema level (Tier 1).

Stage C (2026-08-29) retired the testing and Realtime-check rows that the hardening pass completed. Audit date ranges now go through `ownedBerlinDateAtOffset()` (Tier 1). Persisted precondition helpers fail fast with the exact recovery grep chain, and the full Wave 1 audit battery follows the current conventions (Tier 2). ESLint rejects raw page-root selectors, positional locators, fixed sleeps, per-test timeout overrides, skipped or focused tests, direct cleanup markers, and `visibleText(...).toHaveCount(0)` in specs. Unit convention tests check serial mode, negative-check presence, staged Golden tags, audit tags, date ownership, and precondition recovery text (Tier 2). The Realtime import ban covers alias and relative imports, and `realtime:check` verifies exact replica-index columns plus INSERT, UPDATE, and DELETE publication flags (Tier 2). The optimistic-mutation and cross-battery-lock candidates remain open because Stage C did not make either rule structural.

P1-19 follow-up hardening (2026-08-30) retired three more lessons. Owner audit of Stage C (2026-08-29) left two small non-rule cleanups for the next harness touch, so the certified closure sources stayed untouched: `tests/golden/gg-01.spec.ts` and `tests/golden/p1-03.spec.ts` still carry unguarded chained module state (the precondition module supports `suite: 'golden'` but the retrofit deliberately scoped guards to the audit battery), and `visibleMatchingText` is defined identically in both `tests/audit/support/a1-steps.ts` and `tests/audit/support/p1-13-steps.ts` (fold into one shared support home).

P1-18's product protections landed with the slice, but its run-discipline review exposed seven avoidable fresh-world runs that the original closure did not enforce. The 2026-08-30 follow-up rejects suite-wide “focused” selections and the learned incomplete A1 producer chain before world creation (Tier 1); blocks unclassified or repeated same-class focused retries, requires the mapped P1-16 proof before Golden certification after field-work-pack changes, and checks DEV migration parity in cloud preflight (Tier 2). The UI/UX hardening pass (2026-09-03 to 2026-09-04, [ledger](../plans/uiux-hardening-2026-09.md)) landed its lessons directly. Tier 1: one permissive `uuidSchema` for every validator; the `Field` primitive owning label, marker, helper and error wiring; the `PageShell` column and dynamic-viewport shell; a custom `TimeInput` on every web pointer type; `TableRow`/`ListRow` owning hover through `interactive`; each list rendering header and skeleton from one column definition; `RefreshButton` preserving loaded rows; `PendingSubmitButton` owning the pending interval of plain Server Action forms; `useSettleOnChange` joining props-driven mutations to their authoritative read; `RowActionsMenu` owning a stable menu boundary for rows that can remount under optimistic or Realtime reconciliation; and the shared optimistic-list, pending-row and row-busy primitives. Tier 2: ESLint bans on the strict uuid check, native date, time, month, week, number, range, checkbox and radio inputs, raw `role="alert"`, hand-rolled page columns, `h-screen`, labels outside a `Field`, the row hover literal, and product-code `useTransition`; the development-time option-count guard in `Select`; the 375 px viewport audit; `lib/ui/skeleton-pairing.test.ts`; `lib/ui/custom-time-input.test.ts`; and `lib/ui/tailwind-source.test.ts`. Phase 5 and closure proofs also promoted semantic member navigation to a real link and kept optimistic notification controls mounted through settlement (Tier 1), with persisted-state waits in the shared Golden helpers and P1-23 setup (Tier 2).

Phase 6 exposed a test-architecture debt rather than a reason to discard the test canon. The final campaign attempted the exhaustive audit repeatedly while UI and harness corrections were still moving: 15 failed audit certifications (10 harness assumptions and five product defects) plus one operator-cancelled environment run consumed about 9.1 hours of recorded machine test time across 21 complete-battery attempts. The corrective boundary is deliberately deferred to the pre-Wave-3 testing-system overhaul: preserve Golden/Audit/Canary responsibilities, flow IDs, business assertions, environment separation and the three-tier enforcement ladder, but make audit consumers independently seeded or checkpointed, expose cumulative run cost and progress, make prerequisite chains explicit, and stop using a full battery as a discovery loop. The incident-level evidence and the bounded closure rule live in the [incident log](test-incident-log.md) and UI/UX [ledger](../plans/uiux-hardening-2026-09.md).

The bounded closure audit then retired two product correctness lessons instead of parking them as test prose. `projectLegacyEntriesForWindow` applies approved corrections and makes an out-of-period corrected fact unavailable to the period calculation before interval pairing (Tier 1); `legacy-projection.test.ts` reproduces the August-open/December-close failure and the legitimate move-out-of-window case (Tier 2). This prevents a later-period correction from suppressing an earlier period's `missing_clock` close blocker. Aufträge creation pickers consume the same confirmed client-owned collections as their table and exclude temporary optimistic inserts, so a successful create is immediately available to the next related create without permitting an invalid temporary foreign key (Tier 1); the A1 browser flow is its Tier 2 regression proof.
