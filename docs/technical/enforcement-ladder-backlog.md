# Enforcement-Ladder Backlog

Status: living — last reviewed 2026-09-03

The open conversion candidates from the 2026-08-27 three-part audit (code comments, docs, skills) under [decision 0005](../decisions/0005-enforcement-ladder.md). Each row names the rule, where it lives as prose today, and the concrete mechanism that would enforce it. Remove a row when its conversion lands (and annotate the owning doc "enforced by …"); add rows as new lessons appear.

Stage A of that phase (2026-08-28) added its own protections directly rather than through this backlog: run-policy pins the canary suite to the cloud target and the preflight refuses any run whose `.env.local` routing does not match the requested target (Tier 1); retained-world cleanup refuses a backend mismatch (Tier 1); the untracked-file fingerprint uses NUL-separated git output (Tier 1); local-stack health probes carry named remedies and the canary pins the HIBP copy and migration-history parity (Tier 2). The owner review after Stage A extended the rerun budget to every certification suite — it was golden-only, which let eight same-class audit certification retries run ungated during the Stage A campaign (Tier 2, `scripts/run-playwright.ts`).

Stage B (2026-08-28) retired four Tier 1 rows and two Tier 2 rows by landing them, and added its own protections: the `RealtimeTable` type derives from the one `REALTIME_TABLES` list and the provider generates every binding from it, so a table cannot subscribe without its organization filter (Tier 1 by construction); `useLiveView`/`useRealtimeRouterRefresh` expose no debounce option, so the 150 ms floor cannot be undercut (Tier 1 by construction); `bun run realtime:check` — also part of the local preflight — diffs the list against the database publication and replica-identity state (Tier 2); ESLint bans async `startTransition` callbacks, `setInterval` (named wall-clock exceptions), and `useRealtimeEvent` imports outside the live-view family (Tier 2); replica identity `USING INDEX` makes the DELETE payload leak unwritable at the schema level (Tier 1).

Stage C (2026-08-29) retired the testing and Realtime-check rows that the hardening pass completed. Audit date ranges now go through `ownedBerlinDateAtOffset()` (Tier 1). Persisted precondition helpers fail fast with the exact recovery grep chain, and the full Wave 1 audit battery follows the current conventions (Tier 2). ESLint rejects raw page-root selectors, positional locators, fixed sleeps, per-test timeout overrides, skipped or focused tests, direct cleanup markers, and `visibleText(...).toHaveCount(0)` in specs. Unit convention tests check serial mode, negative-check presence, staged Golden tags, audit tags, date ownership, and precondition recovery text (Tier 2). The Realtime import ban covers alias and relative imports, and `realtime:check` verifies exact replica-index columns plus INSERT, UPDATE, and DELETE publication flags (Tier 2). The optimistic-mutation and cross-battery-lock candidates remain open because Stage C did not make either rule structural.

P1-19 follow-up hardening (2026-08-30) retired three more lessons. Contextual document uploads now use one `DocumentUploadTarget` discriminated union from the component boundary through both server actions, so a missing or mixed owner target does not compile (Tier 1). Dispatch-visible fixtures use `dispatchOverviewBerlinDateAtOffset()`, which shares the product's maximum offset and rejects dates outside the panel window (Tier 1); the convention unit test pins the bounds (Tier 2). `bun run types:generate` and `bun run types:check` pin Supabase 2.116.0, Prettier 3.6.2, the DEV project and both generated schemas, so formatter drift no longer hides the schema delta (Tier 2).

The P1-21 CodeRabbit follow-up (2026-09-01) retired the invocation-rules row after two agents mistook PATH failures for a missing installation. The repository now exposes `bun run review` as the only supported path; it targets the configured WSL binary directly and refuses to install or reinstall anything (Tier 1 for agent workflow). PowerShell shims and a WSL PATH link remove both known false-negative probes on this workstation (Tier 1 for host behavior). Unit tests and `docs:check` pin the wrapper and reject raw installer or CLI instructions in agent-facing files (Tier 2).

Owner audit of Stage C (2026-08-29) left two small non-rule cleanups for the next harness touch, so the certified closure sources stayed untouched: `tests/golden/gg-01.spec.ts` and `tests/golden/p1-03.spec.ts` still carry unguarded chained module state (the precondition module supports `suite: 'golden'` but the retrofit deliberately scoped guards to the audit battery), and `visibleMatchingText` is defined identically in both `tests/audit/support/a1-steps.ts` and `tests/audit/support/p1-13-steps.ts` (fold into one shared support home).

P1-18's product protections landed with the slice, but its run-discipline review exposed seven avoidable fresh-world runs that the original closure did not enforce. The 2026-08-30 follow-up rejects suite-wide “focused” selections and the learned incomplete A1 producer chain before world creation (Tier 1); blocks unclassified or repeated same-class focused retries, requires the mapped P1-16 proof before Golden certification after field-work-pack changes, and checks DEV migration parity in cloud preflight (Tier 2). Only host-side command polling remains Tier 3: the repository can suppress progress output and instruct agents to wait once, but it cannot control the Codex app's command-session polling schedule. That conversion belongs in the agent harness, not this codebase.

## Post-Wave-2 documentation audit (2026-09-03)

A fresh-context audit of every doc, skill, and the code they describe found the drift classes decision 0004 predicted: volatile counters restated in living docs, seven incompatible status-line formats, index rows disagreeing with their targets, and product-status prose in `AGENTS.md` that was one wave behind. The prose was fixed in the owning docs the same day. What climbed the ladder:

- Tier 2, landed in `scripts/check-docs.ts`: status line on line 3 in the genre's exact shape; backtick doc paths inside `docs/` rejected outside append-only logs; index status prefixes compared with the target doc; roadmap accepted counter, ready-set recomputation, and complete-row-to-slice-record linkage with date parity; user-flow-catalog section order, unique sequential flow IDs, and invariant counts.
- Tier 2, landed in the harness: `tests/golden/p1-07.spec.ts` and `p1-12.spec.ts` carry their `@P1-NN` tag, so a certification failure in either can satisfy the runner's focused-proof rule without an override.
- Tier 3 by removal: test counts, spec inventories, duration baselines, and "latest parity checkpoint" paragraphs left `testing.md`, `environments.md`, and `realtime-and-caching.md`; the commands that produce them and the append-only gate log are the only homes.

Open candidates from the same audit, added to the tables below: proxy prefix parity, `server-only` on the storage adapter, inventory ledger immutability, docs review-date staleness, and dead public API routes.
