## Caption

Everyone asked the same question after my last post: how does this actually look when you're using a real knowledge graph? So I built it and recorded it.

Same prompt, four runs. A customer wants an £800 refund in March, and the question is who signs it off. The answer is three hops away and it's split across separate documents, with decoys planted on purpose. Refunds over £500 need ops manager approval. The ops manager is Sarah. Sarah is out of office for all of March, and Marcus Webb is her cover.

The results:

Fable 5 with no graph gets there, but it greps the corpus, reads files, and burns 20 seconds and around 4,000 tokens doing it.

Fable 5 with the graph answers from memory. Eight facts recalled, 2ms, a handful of tokens, zero tool calls.

Haiku 4.5 with no graph falls apart. It asks which organisation I mean, then decides the founder signs it off. Completely lost.

Haiku 4.5 with the graph gets it right. Marcus Webb, same eight facts, same 2ms.

The mechanism is a deterministic prompt injection through a UserPromptSubmit hook. Retrieval never touches the model. There is no tool call, no search, no reasoning step where it can go wrong, and that's exactly why the small model stops failing. OpenAI has hooks for this too, so the pattern isn't Claude specific.

The repo is in the artifact below. It covers pull vs push, the ontology and the logical model, how to set the hooks up, the tiers of implementation, the evals, and a getting started guide. Everything you need to build your own.
